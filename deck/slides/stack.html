Q5 · Which tool carries each part?

Remove any layer and the demo stops working.

River AI

LoRA on an open-weight model, trained on the crossing log, so the judgment is ours

without it: the decider stays rented

Jev

Share, hold or discard in under a second at runtime

without it: a 3 s LLM call per crossing

Talos

Scoped token per role, decider, audit row per crossing, revoke

without it: sharing means leaking

GBrain

One memory graph per room, durable across sessions

without it: nothing to share

QM

One room per role; Talos sits on the memory route QM already exposes

without it: no walls to govern

Superset

Two coding agents building in parallel workspaces

without it: slower build, same demo

Jev is not a host; it is the runtime decider because it is fast and this crowd knows it. If it misbehaves, rules take its place and River is unchanged. QM (from its README): rooms with scoped memory, files, keychain, permissions and a durable sandbox; memory can be routed to an external provider; no documented hook on tool calls or writes, so do not say plugin. River (from its API docs, preview v0.1): LoRA and RL on open-weight models roughly 35B to 1T, Python client. Full notes: docs/sponsors.md in the repo.
