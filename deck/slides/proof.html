Q7 · How do we know it worked?

One audit table. Every claim on stage is a view of it.

Git receipts

  • Each room commits as its own author on its own branch
  • One commit per step, the crossing id in the message
  • The stop is a commit: contract changed, crossing c-042

Timeline

  • Two swimlanes from the audit log, one per room
  • A line across when something crosses, red when denied
  • Seconds from change to the other agent knowing, per run

Inside each agent

  • OpenTelemetry traces via Langfuse or Phoenix, free tier
  • Answers is this just polling: one unrelated call, carrying the change
  • For us to check, not for the stage

Output is good

  • Product tests green after the stop
  • Five runs each, decider off vs on: stale actions counted
  • Override rate: low, and not zero

Access is real

  • Live negative tests: Frontend reads Backend's note, denied
  • QA writes into a code room, denied; a third agent asks, denied
  • Revoke Frontend: next call denied, all three in red on the timeline

Next: how do we build it in four hours?

Build the audit table first on Sunday; the timeline, the access proof and the training set are all views of it. Show the denials live, not from CI. Never say instantly: the clock prints the seconds.
