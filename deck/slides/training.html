Q4 · How does the decider get better?

Train the decider only. The rooms' agents generate; the decider learns to judge.

What gets trained

  • Two classifiers behind one signature: kind of change, and share / hold / discard with targets
  • Not the coding agents, not the memory. Facts stay in GBrain; judgment goes in the weights
  • Jev cannot be tuned: same weights for every account. So v2 is our own model: a LoRA on an open-weight base via River. Rules and Jev stay as baselines

Training rows

  • Input: change text, author room, kind if known, the option order shown
  • Label: verdict and targets. Ground truth: the override key, pressed or not
  • Public rows for the first pass (next slide); the demo log is the held-out set

Method

  • Supervised LoRA, one epoch first, low learning rate, stop early on held-out loss
  • Pin the model version; log option order so order sensitivity is measurable
  • Started at hour three on event credits. If it is slow: Jev's probabilities as features into a small classical model, also ours, microseconds

Evaluation

  • Held-out 20 percent, stratified by kind
  • Metric: agreement with human verdicts, reported per class, against the rules-only baseline
  • Bar: beat rules on held-out rows, or say so on stage. Report the confusion matrix, not one number
